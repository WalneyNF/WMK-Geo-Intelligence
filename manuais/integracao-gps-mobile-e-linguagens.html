2. Entenda a arquitetura

Aplicativo móvel ou web → backend autorizado → API GPS
                                     ↓
                           banco / histórico
                                     ↓
                           consulta por HTTP
                                     ↓
                        mapa Leaflet ou 3D

Para enviar posições de rastreadores, prefira a API de um backend autenticado ou protocolos suportados pelo Tracker. Não coloque credenciais do servidor dentro de apps distribuídos. O exemplo móvel aqui apenas consulta posições e não captura nem transmite a localização do aparelho.

6. React Native, Kotlin e Swift

React Native: crie um projeto Expo TypeScript e copie react-native/App.tsx. Ajuste a constante API para o servidor acessível pelo telefone. O exemplo mostra uma lista de dispositivos; não é um aplicativo completo de mapa.

Kotlin: crie um projeto Android Studio com Activity baseada em ComponentActivity, adicione a permissão android.permission.INTERNET no AndroidManifest e integre o trecho MainActivity.kt. Configure endpoint HTTPS e autenticação.

SwiftUI: crie um projeto iOS no Xcode, adicione WMKGPSView.swift e apresente a view no ponto de entrada. Configure endpoint HTTPS acessível e autorizado. Não foi testado em dispositivo Apple.

Atenção: 127.0.0.1 dentro do telefone aponta para o próprio telefone. O servidor do PC precisa ser alcançável e protegido. Não exponha a ponte de laboratório diretamente à internet.

7. Contrato JSON e teste

{
  "id": "WMK-TS-001",
  "latitude": -22.281,
  "longitude": -42.532,
  "simulated": true
}

O endpoint de escrita é POST /api/v1/external/positions, com cabeçalho privado X-WMK-API-Key. HTTP 202 significa evento aceito, não que foi exibido automaticamente no mapa 3D. A consulta externa GET /api/v1/external/positions retorna eventos; a consulta do simulador GET /api/v1/vehicles?source=simulator retorna veículos normalizados. Cada integração deve validar o formato da resposta e tratar indisponibilidade.

8. Segurança e publicação

Para uso real: autenticação por usuário e dispositivo, HTTPS, autorização de leitura, armazenamento seguro, limites de requisições, trilha de auditoria, descarte de posições antigas e LGPD. O código da biblioteca é didático e deve ser adaptado e testado antes da produção. Mantenha créditos e licenças dos projetos originais.
