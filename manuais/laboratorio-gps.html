1. O que estamos construindo?

Três programas independentes que podem se comunicar. O GPS Tracker recebe e guarda posições; o Geo Bridge consulta a API autenticada e converte os dados em JSON; o Geo Intelligence pode apresentar esses dados. A página do laboratório é uma ferramenta de testes separada do mapa 3D principal.

GPS / Celular → GPS Tracker (8082: API) → Geo Bridge (8768) → Laboratório (4173)

2. Por que HTTP 503?

No teste de 06/11/2026, /api/v1/capabilities retornou traccarConfigured: false. Isso significa que o processo Bridge não recebeu usuário/senha ou token do Tracker. O Bridge retorna 503 com traccar_auth_not_configured. O Tracker exige autenticação para acessar dispositivos; sem login, a API retorna 401.

CódigoInterpretação
200Requisição atendida; confira se os dados estão corretos.
401Autenticação necessária ou negada.
502Bridge não conseguiu obter resposta válida da fonte.
503Credenciais do Tracker ausentes no processo Bridge.

3. Primeiro teste — sem senha

Abra o PowerShell e execute:

Invoke-RestMethod 'http://127.0.0.1:8082/api/server'
Invoke-RestMethod 'http://127.0.0.1:8768/health'
Invoke-RestMethod 'http://127.0.0.1:8768/api/v1/capabilities'

Se os três responderem, os serviços estão acessíveis. Isso ainda não comprova a integração autenticada.

4. Como configurar a autenticação

Entre em WMK GPS Tracker com uma conta de laboratório. Não envie senha pelo chat, nem a coloque no Git. Abra um novo PowerShell, sem parar a instância atual do Bridge, e execute:

cd D:\Ferramentas\WMK-Geo-Bridge
$env:WMK_BRIDGE_PORT = '8769'
$env:WMK_TRACCAR_URL = 'http://127.0.0.1:8082'
$env:WMK_TRACCAR_USER = Read-Host 'Usuário Traccar'
$senha = Read-Host 'Senha Traccar' -AsSecureString
$ptr = [Runtime.InteropServices.Marshal]::SecureStringToBSTR($senha)
try {
  $env:WMK_TRACCAR_PASSWORD = [Runtime.InteropServices.Marshal]::PtrToStringBSTR($ptr)
} finally {
  [Runtime.InteropServices.Marshal]::ZeroFreeBSTR($ptr)
}
py -3 src/bridge.py

Esse exemplo serve para laboratório local. Variáveis de ambiente não substituem um cofre de segredos. Mantenha o serviço acessível apenas localmente.

5. Como usar a tela

Abra o laboratório GPS. Digite http://127.0.0.1:8769 no campo de endereço. Clique em Verificar API e depois em Atualizar veículos. Confira nome, latitude, longitude, velocidade e horário. Ative atualização a cada dez segundos para testar polling. Se o Vite não estiver na porta 4173, o Bridge poderá bloquear o acesso por CORS.

6. O que é uma API REST?

É uma interface HTTP que outros programas consultam. Por exemplo, GET /health informa se o Bridge está vivo; GET /api/v1/capabilities informa recursos e configuração; GET /api/v1/vehicles devolve uma lista JSON. O Bridge 0.1 não implementa autenticação própria de leitura; não o exponha na internet.

7. Exercícios para aprender

  1. Compare o retorno de /health e /vehicles com o Bridge sem credenciais.
  2. Cadastre um dispositivo fictício no Tracker.
  3. Execute o Bridge autenticado em 8769 e consulte os veículos.
  4. Compare os campos JSON com a tabela do laboratório.
  5. Desligue o Bridge e verifique se o mapa 3D principal continua abrindo.
  6. Identifique por que um dispositivo pode existir mas não ter posição GPS.

8. Próximos níveis

Estude os contratos JSON, a conversão de velocidade de nós para km/h, autenticação, autorização, CORS, HTTPS, testes automatizados, consentimento e LGPD. A integração visual dos veículos no mapa 3D principal ainda exige desenvolvimento e testes adicionais.
