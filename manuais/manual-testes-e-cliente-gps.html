1. O que você vai aprender?

Vamos construir uma página web simples que solicita dados de veículos a uma API local e mostra os resultados numa tabela. Ela não usa React, bibliotecas externas, banco de dados ou mapa 3D. Assim você aprende o essencial antes de adicionar recursos complexos.

Você precisa do navegador, do servidor web Vite já iniciado para o Geo Intelligence e de uma ponte GPS ativa. O teste confirmado utiliza http://127.0.0.1:8766, que lê posições simuladas dos quatro carros. A porta 8768 é outro serviço: o WMK Geo Bridge independente, que exige credenciais para consultar o Traccar.

Regra de ouro: o cliente não deve receber usuário ou senha do Traccar. O servidor intermediário cuida da autenticação. A API de laboratório fica restrita à máquina local.

2. Verificando os serviços no PowerShell

Abra o PowerShell e execute um comando por vez:

Invoke-RestMethod 'http://127.0.0.1:8766/health'
Invoke-RestMethod 'http://127.0.0.1:8766/api/v1/capabilities'
Invoke-RestMethod 'http://127.0.0.1:8766/api/v1/vehicles?source=simulator'

O primeiro confirma que a ponte responde. O segundo descreve as fontes disponíveis. O terceiro devolve a lista de veículos. No teste confirmado, a ponte devolveu quatro registros simulados. Se aparecer count: 4, os dados estão disponíveis na API. Se o servidor não responder, verifique se a ponte Python está executando.

Para entender a outra ponte, compare:

Invoke-RestMethod 'http://127.0.0.1:8768/health'
Invoke-RestMethod 'http://127.0.0.1:8768/api/v1/capabilities'

Na instância observada, traccarConfigured: false significa que a fonte Traccar ainda não foi autenticada. Portanto /api/v1/vehicles retorna HTTP 503. Isso não impede o teste simulado na porta 8766.

3. Seu primeiro teste no navegador

  1. Abra o exemplo didático no navegador.
  2. Confira que o campo da API contém http://127.0.0.1:8766.
  3. Clique em Consultar veículos.
  4. Verifique se a tabela mostra quatro carros, coordenadas, velocidade e horário.
  5. Marque Atualizar a cada 10 segundos e acompanhe as mudanças.
  6. Desmarque a opção para interromper somente as consultas automáticas do navegador.

Se a tabela aparecer, você comprovou que seu HTML consegue consumir a API via JavaScript. Isso é diferente de comprovar a ingestão física de GPS no Tracker.

4. Como criar essa aplicação do zero

Na pasta D:\Ferramentas\WMK-Geo-Intelligence\app\exemplos\cliente-gps\, criei três arquivos independentes:

ArquivoO que faz?
index.htmlDefine os elementos da interface: título, campo URL, botões, status e tabela.
style.cssDefine as cores, fontes, espaçamentos, tabela e aparência responsiva.
app.jsFaz as requisições HTTP, interpreta o JSON, atualiza a tabela e controla o temporizador.

Para estudar, copie esses três arquivos para outra pasta de desenvolvimento e faça alterações nela. Sirva os arquivos por um servidor HTTP; não confie em abrir diretamente como file://, pois a política de origem do navegador pode impedir requisições.

O exemplo está integrado ao servidor de desenvolvimento do projeto e pode ser acessado por http://127.0.0.1:4173/exemplos/cliente-gps/. Se o Vite estiver em outra porta, adapte o endereço.

5. Entendendo o HTML

<label for="url">Endereço da API</label>
<input id="url" value="http://127.0.0.1:8766">
<button id="consultar">Consultar veículos</button>
<p id="estado" role="status">Aguardando consulta</p>
<tbody id="linhas"></tbody>
<script src="./app.js" defer></script>

O atributo id permite que o JavaScript encontre o elemento. O label explica o campo. O tbody é a região da tabela que será preenchida. defer faz o script executar depois da análise do HTML, quando os elementos já existem. role="status" ajuda tecnologias assistivas a identificar mensagens de atualização.

6. Entendendo o CSS

body {
  background: #07140f;
  color: #e0f6e8;
  margin: 0;
}
button {
  background: #33d17a;
  cursor: pointer;
}
.scroll { overflow-x: auto; }

O CSS não consulta a API; ele apenas apresenta a interface. A classe .scroll permite rolar a tabela horizontalmente em telas menores. As classes .erro e .sucesso diferenciam visualmente os resultados das operações.

7. Entendendo o JavaScript

7.1. Construir a URL

const url = new URL('/api/v1/vehicles', 'http://127.0.0.1:8766');

O construtor URL combina o endereço-base com o caminho do endpoint. Isso evita erros comuns com barras duplicadas.

7.2. Consultar a API

const resposta = await fetch(url.toString(), { cache: 'no-store' });
if (!resposta.ok) throw new Error('HTTP ' + resposta.status);
const dados = await resposta.json();

fetch envia uma requisição GET. await espera a resposta sem travar o navegador. response.ok é verdadeiro para respostas HTTP 2xx. .json() converte o corpo JSON para objetos JavaScript. cache: 'no-store' evita reutilizar resposta armazenada pelo cache HTTP.

7.3. Validar o contrato

if (dados.schemaVersion !== '1.0' || !Array.isArray(dados.items)) {
  throw new Error('Formato JSON inesperado');
}

Validar o formato impede que a aplicação trate uma mensagem de erro ou uma versão incompatível como se fosse uma lista de veículos. É uma validação inicial; sistemas de produção devem validar também tipos, limites e permissões.

7.4. Construir a tabela com segurança

const td = document.createElement('td');
td.textContent = String(veiculo.name);
linha.append(td);

O uso de textContent impede que nomes retornados pela API sejam executados como HTML ou JavaScript. Evite usar innerHTML com conteúdo não confiável.

7.5. Atualização automática

setInterval(() => {
  if (document.getElementById('automatico').checked) consultar();
}, 10000);

O temporizador dispara a cada dez segundos. Esse padrão é chamado polling. A variável consultando evita requisições simultâneas caso uma resposta demore. Polling não é o mesmo que WebSocket ou transmissão instantânea de eventos.

8. Como entender o JSON

{
  "schemaVersion": "1.0",
  "source": "simulator",
  "count": 1,
  "items": [{
    "id": "WMK-NF-CARRO-001",
    "name": "Carro de teste 01",
    "simulated": true,
    "position": {
      "latitude": -22.28,
      "longitude": -42.53,
      "speedKmh": 35,
      "timestamp": "2026-11-07T00:55:13Z"
    }
  }]
}

Este é um exemplo fictício de resposta. items é um array; cada elemento representa um veículo. position pode ser null. Latitude e longitude são coordenadas em graus decimais. speedKmh é a velocidade em quilômetros por hora. timestamp é o horário da posição; não necessariamente a hora em que a página consultou a API. simulated: true indica dados fictícios.

9. Problemas comuns e soluções

ProblemaComo investigar
HTTP 503 na porta 8768O Bridge principal pode estar sem credenciais do Tracker. Consulte /api/v1/capabilities.
Erro de rede / Failed to fetchConfirme o servidor, a porta e a política CORS. Teste /health no navegador.
HTTP 200, mas zero veículosA API respondeu; verifique a fonte e se existem dispositivos.
Velocidades não mudamVerifique o simulador Python, o arquivo de eventos, a caixa de atualização automática e os timestamps.
Erro de JSONConfira se a resposta possui schemaVersion: "1.0" e items como array.
Abriu como file://Sirva a página por HTTP usando Vite ou outro servidor local, respeitando as origens CORS permitidas.

Como registrar: para cada teste anote data, versão, comando, resultado esperado, resultado observado e situação (aprovado/reprovado/bloqueado). Os testes de interface devem ser executados no navegador; a disponibilidade HTTP por si só não comprova todos os cliques.

11. Segurança e integração em sistemas de terceiros

Para incluir esta funcionalidade em outro projeto, copie a lógica de consulta e adapte o layout, mantendo o contrato JSON. Não exponha credenciais no JavaScript. A versão de laboratório está vinculada a 127.0.0.1 e não foi preparada para acesso público. Para implantação externa, implemente autenticação própria, autorização por dispositivo, HTTPS, política CORS restrita, limitação de requisições, auditoria e proteção de dados de localização conforme a LGPD.

As três aplicações WMK podem operar isoladamente. O cliente HTML é um exemplo opcional de integração, não uma dependência obrigatória do Tracker ou do Geo Intelligence.

12. Exercícios para aprender de verdade

  1. Básico: altere o título do HTML e a cor do botão no CSS.
  2. Básico: adicione uma coluna com o identificador id do dispositivo.
  3. Intermediário: adicione um filtro que mostre apenas veículos com velocidade superior a 40 km/h.
  4. Intermediário: crie um contador de consultas realizadas.
  5. Intermediário: exiba o tempo decorrido desde position.timestamp, tratando posições ausentes.
  6. Avançado: implemente cancelamento de requisição com AbortController.
  7. Avançado: crie testes automatizados para HTTP 200, 503, JSON inválido e dispositivos sem posição.
  8. Avançado: separe a camada HTTP da camada de renderização para reutilizar o cliente num mapa 2D ou 3D.

Critério de conclusão: você consegue explicar o caminho Python → API HTTP → fetch → JSON → DOM, reproduzir os testes e distinguir dados simulados de posições reais.
