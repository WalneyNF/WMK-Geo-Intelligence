              ↓ POST JSON autenticado
   WMK GPS Bridge laboratório :8770
              ↓ grava eventos JSONL
   GET /api/v1/external/positions
              ↓ fetch no navegador
          Mapa Leaflet

Simulador Python → Bridge :8766
              ↓ GET /api/v1/vehicles?source=simulator

Os exemplos enviam coordenadas fictícias, marcadas com simulated:true. O navegador consulta as duas APIs e exibe círculos de cores diferentes. O mapa é um exemplo didático separado, não uma alteração no mapa 3D principal. A porta 8770 é uma instância de teste: só funciona quando a ponte está em execução nela.

2. Preparar o receptor de testes

Abra PowerShell em D:\Ferramentas\traccar\laboratorio-gps e execute:

$env:WMK_BRIDGE_PORT = '8770'
$env:WMK_BRIDGE_WRITE_KEY = Read-Host 'Crie uma chave temporária'
py -3 wmk_bridge.py

Deixe esse terminal aberto. Em um segundo PowerShell, informe a mesma chave para os programas clientes:

$env:WMK_BRIDGE_WRITE_KEY = Read-Host 'Informe a chave temporária'
$env:WMK_GPS_URL = 'http://127.0.0.1:8770'

Não grave a chave no repositório. Os exemplos são para uso local; não exponha essa ponte diretamente à internet.

Para adaptar a qualquer linguagem, reproduza os mesmos elementos: método POST, URL, cabeçalho de autenticação, Content-Type: application/json e corpo com ID, latitude, longitude e indicação de simulação.

4. Como criar um mapa em HTML/CSS/JavaScript

Abra mapa.html. O arquivo carrega a biblioteca Leaflet 1.9.4 e os mapas-base do OpenStreetMap. Essa etapa depende de conexão com a internet para carregar a biblioteca e os mosaicos do mapa.

O código está separado em mapa.js. Ele executa duas consultas em paralelo, usando Promise.allSettled, para que uma fonte indisponível não impeça a exibição da outra:

const [sim, ext] = await Promise.allSettled([
  fetch('http://127.0.0.1:8766/api/v1/vehicles?source=simulator'),
  fetch('http://127.0.0.1:8770/api/v1/external/positions')
]);

Na implementação real, uma função ler() verifica o código HTTP e converte o JSON. A fonte do simulador usa objetos position; a fonte externa usa latitude e longitude diretamente. O JavaScript normaliza esses dois formatos antes de criar marcadores com L.circleMarker. Verde indica simulação; azul indica eventos externos. Um Map mantém somente o último evento recebido por identificador externo. A opção de atualização automática consulta novamente a cada dez segundos.

Limite importante: este mapa não é um rastreador completo com trilhas, reprodução temporal ou persistência própria. É uma demonstração de leitura e visualização. Não insira chaves secretas em JavaScript do navegador.

6. Como alimentar seus próprios forks

Um programa externo pode enviar eventos para o receptor Python sem depender do simulador. O Geo Intelligence pode ler esses eventos no exemplo Leaflet. Para integrar ao mapa 3D principal, é necessário adicionar uma camada de normalização de fontes, mantendo IDs, coordenadas, timestamp, origem e sinalização de dados simulados.

O WMK GPS Tracker (Traccar) tem outro caminho: dispositivos compatíveis enviam dados para um receptor de protocolo, e a ponte consulta a API autenticada do Tracker. Os quatro testes de envio HTTP externo não comprovam que esse caminho real esteja configurado.

Para C#, Java, Visual FoxPro e outras linguagens, o contrato HTTP é o mesmo; exemplos dessas linguagens ainda devem ser implementados e executados antes de receberem selo de aprovação.

8. Exercícios progressivos

  1. Modifique o identificador do veículo Node e envie outra posição.
  2. Altere a latitude e longitude no exemplo Python e compare no mapa.
  3. Crie um quinto cliente em outra linguagem usando o mesmo contrato.
  4. Adicione um filtro por fonte no mapa.
  5. Exiba o horário e destaque posições antigas.
  6. Faça um teste de rede interrompendo a ponte externa e observe a mensagem.
  7. Implemente testes automatizados para HTTP 202, 400, 401 e 403.
  8. Adapte os eventos externos para o contrato de veículos da API principal, com testes de regressão.
